## Findings

### R1 - P1: Shared-boundary evidence can change without invalidating geometry approvals

Location: [ToolboxBoundaryDependencies.cs:116](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxBoundaryDependencies.cs:116). Source: edge. AC7-9, AC12.

Coverage requires segment/point consumption by a physical boundary but does not require the boundary's `EvidenceIds` to feed its dependency node. A second source's evidence can feed only the case node and still produce zero coverage issues. Accept a rerun changing that evidence and its source hash while retaining boundary metadata and the old primary-evidence check reviews: readiness remains `Ready`, `GeometryApproved` stays true, and both shared parcels' prior dispositions remain current.

Fix: require source/evidence-to-boundary dependency coverage for every declared supporting evidence item and bind those actual inputs into consuming parcel/check fingerprints. Regression must reject missing coverage and invalidate both former approvals after evidence/hash changes.

### R2 - P1: Archived manual applicability cannot be repaired after another lineage/key change

Location: [ToolboxParcelLineage.cs:65](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxParcelLineage.cs:65), [ToolboxReconciliation.cs:217](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxReconciliation.cs:217). Sources: edge + auditor. AC10-11, AC15.

Applicability validation permits only current manual entity IDs, findings and human-review IDs. After a split, an archived parent's manual link points to a child key. A later explicit key regeneration or split/merge retires that target and creates a readiness barrier. An evidence-backed repair of the archived manual link throws `Invalid finding/correction applicability audit`, because its original manual entity is no longer in the valid-record inventory. The case remains blocked even with fresh checks.

Fix: include same-case archived correction identities and retain their original provenance while permitting append-only subsequent applicability decisions. Test split -> regenerated key and split -> merge, including a negative foreign-archive case.

### R3 - P1: Canonical evidence-link edits leave old checks ready

Location: [ToolboxBoundaryDependencies.cs:170](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxBoundaryDependencies.cs:170) and canonical-input consumption in `ToolboxExamination.cs`. Source: auditor. AC8-9, AC12.

Canonical `evidence_links` are preserved by the contract but absent from dependency input hashing and relationship coverage. Add an evidence-to-parcel association while retaining traces, hashes and geometry: impact reports zero changed/affected IDs and zero unknown coverage, and evaluation with the old reviews remains `Ready`.

Fix: fingerprint relevant evidence/party-to-parcel relationships and require their consuming dependencies. Add, remove and reassign links; invalidate affected reviews/decisions while preserving unrelated geometry-only results where appropriate.

### R4 - P2: Case-wide findings ignore accepted applicability dispositions

Location: [ToolboxParcelLineage.cs:26](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxParcelLineage.cs:26), [ToolboxExamination.cs:301](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxExamination.cs:301). Sources: blind + edge + auditor. AC11-12.

`FindingParcels` expands an empty original parcel scope to all current parcels before consulting applicability. The evaluator skips `NotApplicable` only when original parcel IDs were retired. A case-wide finding can receive an accepted `NotApplicable` link during a split but still apply to both children and block fresh readiness. An explicit narrower `Applicable` link is likewise ignored.

Fix: honor the latest validated applicability decision independently of original scope cardinality. Preserve original finding scope/history; test case-wide not-applicable, narrower applicable and unresolved mappings.

### R5 - P2: Dependency-version changes disappear from impact reporting

Location: [ToolboxBoundaryDependencies.cs:200](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxBoundaryDependencies.cs:200). Sources: blind + edge. AC8-9.

Consumer fingerprints include dependency inventory `Version`, but impact detection compares only actual node input values and incoming edges. Change only the inventory version: a check's consumer fingerprint changes, while impact returns zero changed and zero affected nodes. Report/check/artifact invalidation consumers therefore receive a misleading empty impact result.

Fix: align impact-change semantics with the versioned consumer-fingerprint contract, including relevant node descriptors and relationship versions. Test a version-only change and node-binding changes against affected consumers.

### R6 - P2: Inclusion changes omit consuming decisions/artifacts from impact

Location: [ToolboxBoundaryDependencies.cs:172](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxBoundaryDependencies.cs:172). Source: auditor. AC8-9, AC15.

Parcel dependency inputs hash geometry only; decision inputs hash only their reference ID. Set an included parcel to excluded with explicit audit evidence and retain the graph: impact returns zero changed/affected IDs and zero unknown coverage despite declared parcel -> decision -> case -> artifact dependencies. The aggregate's own inclusion fingerprint does change, but the impact report omits its affected downstream outputs.

Fix: represent inclusion/disposition dependencies in decision/case/artifact inputs without treating a non-geometric scope edit as a geometry change. Test exclusion and re-inclusion impacts plus unchanged geometry-only checks.

### R7 - P2: Accepted value-replacement audit choices are discarded

Location: [ToolboxReconciliation.cs:235](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxReconciliation.cs:235). Source: auditor. AC4, AC11.

Acceptance validates each disposition's actor, reason, evidence and retain/replace choice, but the returned snapshot keeps only rerun candidates, model archives, lineage and operation ID/digest/revision. It does not retain `proposal.Dispositions` or append their audit choices. Once the caller discards the proposal, the accepted replacement's reason/evidence/decision cannot be recovered from the snapshot; a digest cannot reconstruct those fields.

Fix: retain immutable accepted dispositions with operation/revision identity, preserving replay's no-duplicate behavior. Test a manually reviewed coordinate replacement and verify the actor/reason/evidence survives in the returned result without the original proposal.

### R8 - P2: Valid dependency DAGs cause exponential validation work

Location: [ToolboxBoundaryDependencies.cs:84](../../../src/ParcelWorkflowAddIn/ParcelWorkflowAddIn/Workflow/Toolbox/Model/ToolboxBoundaryDependencies.cs:84). Sources: blind + edge. AC8, AC16; graph-validation robustness.

Cycle validation remembers only the active path and restarts from every node; already completed shared descendants are repeatedly traversed. Two nodes per layer connected to both nodes in the next layer create exponential visits in a valid acyclic graph. Local probes with 8/12/14 layers (67/75/79 total nodes including the fixture graph) took approximately 2/20/85 ms; adding four/six nodes multiplied traversal time rather than increasing it proportionally. Larger valid dependency inventories can stall acceptance/readiness. Timings are illustrative, not product benchmarks.

Fix: use a completed-node set plus active-path detection, or a standard linear graph-cycle traversal. Test deep/shared DAGs and retained cycle rejection without relying on fragile wall-clock thresholds.
