# Investigation: TR 100000627 M-Geo Restore Message

## Hand-off Brief

1. **What happened.** Confirmed: clicking M-Geo for TR 100000627 tried to restore the saved overlay from the output file geodatabase raster path and ArcGIS reported `Failed to add data, unsupported data type`.

**Detail:** The previous button path called `TryRestoreLocalOverlayFromOutputGeodatabaseAsync`, which builds a raster dataset path in the output GDB and passes it to `LayerFactory.Instance.CreateLayer(new Uri(overlayPath), group)`. If ArcGIS rejects that raster dataset URI as unsupported, the PNG fallback is not attempted by the button path.

## Deduced Conclusions

### Deduction 1: This is not a parcel validation/output failure

**Based on:** Findings 1 and 2.

**Reasoning:** The failing message is emitted while restoring an optional M-Geo visual overlay, after output and validation artifacts already exist and show no warnings/errors.

**Conclusion:** The transaction's computed geometry/output is valid locally; the message is a restore/display problem for the overlay layer.

### Deduction 2: The fix should fall back to the saved image artifact

**Based on:** Findings 3 and 4.

**Reasoning:** The saved PNG/world/projection files are available and are already the source used to create the overlay. If the persisted GDB raster path cannot be loaded as a layer, the restore path should attempt the still-present image artifact.

**Conclusion:** The M-Geo button should call the persisted restore flow, and the persisted restore flow should catch output-GDB raster restore failures and load the PNG fallback.

## Conclusion

**Confidence:** High

The root cause is the M-Geo button using the output-GDB-only restore path. For TR 100000627, ArcGIS rejected the output geodatabase raster path as an unsupported data type, and the UI surfaced that exception instead of falling back to the saved georeferenced PNG artifact. Local validation/output evidence for TR 100000627 is clean; no generated report PDF was present in `output\reports`.

## Recommended Next Steps

### Fix direction

Implemented locally: switch the M-Geo button to `TryRestorePersistedOverlayAsync`, and make that method catch output-GDB raster restore failures before falling back to `artifact.ImagePath` when the saved image exists.

### Diagnostic

After deploying the add-in build, reopen TR 100000627 and click M-Geo. Expected result: the overlay restores from the saved PNG and does not show the unsupported data type restore error.
